### Key architecture decisions
- Separate database, API-only integration with voeq.ng (ADR-001).
- Transactional outbox + pg-boss so notification failure can't lose
  applications (ADR-004) — required by spec §15/§19.
- Two-tier media: private R2 for receipts/private docs, Cloudinary `voeq/` for
  public approved imagery (ADR-005).
- NMU badge → new `institutionalVerifications[]` field on the voeq.ng side,
  not the existing `verified` boolean (ADR-006) — needs marketplace-repo
  agreement.
- Fee model and business categories are per-institution **configuration**, not
  constants (spec §7.3, §4.2).
